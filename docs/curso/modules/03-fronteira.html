A fronteira que explica tudo

Metade deste repositório nunca chega ao seu celular. Entender onde fica essa linha explica quase toda decisão do projeto.

Cozinha de restaurante? Não. Pense num luthier.

O luthier tem bancada, goiva, verniz, estufa. Nada disso vai junto com o instrumento quando você o leva pra casa — você leva só o trompete pronto.

As 43 ferramentas em Python deste repositório são a bancada. O que chega no seu celular é o instrumento.

O nome disso

É um site estático. Não existe servidor rodando código, nem banco de dados, nem conta de usuário. Dizer a uma IA “este é um site estático, não proponha backend” corta metade das sugestões erradas de uma vez.

O arquivo que atravessa a fronteira

build_site.py tem 74 linhas e um trabalho só: pegar os dois lados e juntar numa pasta.

EM PORTUGUÊS

Se já existe uma pasta de site de antes, apaga.

Começar do zero toda vez evita o pior bug de build: sobra de versão antiga.

Copia a pasta app/ inteira — é o app, do jeito que está.

Menos ele mesmo: o script não precisa ir junto para o celular.

Depois enfia os dados de cada jornada em sua subpasta.

🧹
Por que apagar tudo antes

Se o build só sobrescrevesse, um arquivo que você removeu do projeto continuaria vivo no site publicado — às vezes por meses. “Build limpo” é uma expressão que vale usar com a IA.

Duas jornadas, um código só

Cumbias e Sambrass não são dois apps. É o mesmo código lendo pastas diferentes — e a troca é literalmente um prefixo no caminho.

🪘
Cumbias — 16 peças

Busca em ./data/cumbias/ · guarda o progresso em chaves cu2_*

🥁
Sambrass — 110 peças

Busca em ./data/ · guarda o progresso em chaves sb2_*

⚠️
Onde isso morde

As duas jornadas não têm os mesmos arquivos. As cumbias não têm curriculum.json; o Sambrass não tem pitch_warn.json. O app pede os dois de qualquer jeito — e seis pedidos falham em silêncio, toda vez que alguém abre o app. Isso não é bug: é decisão. O próximo módulo mostra como ela foi domada.
