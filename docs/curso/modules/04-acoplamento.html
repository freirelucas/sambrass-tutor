04

O acoplamento invisível

Duas metades do projeto combinaram nomes de arquivo por escrito. Ninguém confere se continuam combinando — até alguém conferir.

Duas pessoas, uma chave embaixo do tapete

Você combina com alguém: “deixo a chave embaixo do vaso da direita”. Funciona por anos. Um dia alguém troca o vaso de lugar — e ninguém avisa.

Não há erro, não há alarme. Só uma pessoa parada na porta, sem entender.

🔑
O vaso deste projeto

O pipeline escreve pieces.json. O app pede pieces.json. Os dois nomes são strings digitadas à mão, em arquivos diferentes, em linguagens diferentes. Nada liga uma à outra.

E por que ninguém percebe quando quebra

Por causa de quatro caracteres. Olhe de novo a linha do módulo 1 — agora só o pedaço que importa:

CÓDIGO · app/app.js:20 

  const get = async (f) => { try { return await (await fetch('./data/' + JCFG().base + f)).json(); } catch { return null; } };
EM PORTUGUÊS

Monta o caminho juntando pedaços de texto: pasta + jornada + nome do arquivo.

O try/catch aqui significa: “se falhar, devolva nada e siga em frente”.

Resultado: um arquivo que sumiu vira null. E null vira tela vazia.

Sem erro vermelho. Sem aviso. Sem pista.

💡
A lição que vale para qualquer projeto

Um catch que engole o erro em silêncio troca um problema barulhento por um problema invisível. Às vezes vale a pena — aqui vale, porque alguns arquivos faltam de propósito. Mas então alguém precisa conferir noutro lugar.

A solução: transformar a ausência em decisão escrita

Existe um script que lê os dois lados e compara. E as ausências legítimas viraram uma lista com motivo escrito:

CÓDIGO · tools/check_contrato.py:30 

OPCIONAIS = {
    ("cumbias", "curriculum.json"): "as cumbias não têm currículo de 6 semanas (isso é do Sambrass)",
    ("cumbias", "rotina.json"): "rotina diária vem do currículo, que as cumbias não têm",
    ("sambrass", "pitch_warn.json"): "validação de alturas só roda no pipeline das cumbias",
}
EM PORTUGUÊS

Uma lista das faltas que são intencionais.

Cada linha diz por que aquele arquivo não existe naquela jornada.

Se não dá para escrever o motivo, provavelmente é bug — não escolha.

E se o arquivo passar a existir, o script falha pedindo para tirar a linha: a justificativa não envelhece virando mentira.

checagens

16 arquivos × 2 jornadas, mais 5 chaves de topo que o app lê lá dentro.

6

faltas declaradas

Cada uma com motivo. Um 404 virou decisão registrada em vez de surpresa.

⛔

falha o deploy

Roda no CI logo depois do build. Nada quebrado chega ao ar.

O mesmo problema, outro disfarce: o CSS

Das seis páginas do app, só uma carrega o style.css. As outras cinco têm o próprio estilo embutido.

Resultado: 157 classes existem só na home. Usar qualquer uma delas noutra página renderiza sem estilo nenhum — e, de novo, sem erro.

🧪
Como se prova que um guard funciona

Não basta ele passar. É preciso quebrar de propósito e ver ficar vermelho. Fazer uma página usar uma classe que ela não tem derruba o CI — foi assim que esse guard foi validado. Peça isso às IAs: “escreva o teste e depois mostre ele falhando”.
